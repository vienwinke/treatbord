# Treatbord 上架前安全与可靠性审核报告

- 审核对象：AGENTS.md 中的技术方案、表结构、接口提案（及评审建议）
- 审核前提：**微信小程序上架 + 生产环境部署**，以安全性和可靠性为底线
- 状态：设计阶段审核（代码尚未编写，本报告作为开发约束）
- 日期：见 git 提交历史

---

## 1. 审核结论摘要

方案基础框架可靠（Java 17 + Spring Boot + MySQL + Redis 成熟稳定），但**按上架标准存在硬性缺口**，主要集中在：

1. **上架合规**：类目资质、隐私政策、内容安全检测是微信审核的强制项，缺一项即无法过审
2. **越权防护（IDOR）**：任务平台天然是多角色操作同一批资源的系统，"审核别人的任务 / 看别人的凭证"是最致命的安全漏洞，必须在设计层定死资源归属校验
3. **幂等与审计**：接取/提交/审核接口的重复调用、状态变更的可追溯性，直接决定生产环境的可靠性

P0 项（上架硬门槛/安全底线）必须在开发前定稿，P1 项随 MVP 一并交付，P2 项可上线后迭代。详见第 7 节。

## 2. 微信小程序上架合规专项

### 2.1 类目与资质（P0，最先确认）

- 「任务接取 / 兼职撮合」类小程序在微信可能归入 **招聘/兼职** 或 **商业服务** 类目，**部分类目要求资质证明**（如《人力资源服务许可证》、营业执照经营范围）——这是上架的最大不确定性，**立项初期就要提交类目审核确认**，否则开发完才发现类目过不了，返工成本极高
- 备用方案：若资质不齐，考虑调整业务表述（如定位为"兴趣互助 / 轻任务社区"）并提前与微信类目规则核对

### 2.2 隐私合规（P0，强制）

- 配置微信《**小程序隐私保护指引**》：逐条声明收集的信息（openid、昵称、头像、位置等）及用途
- 提供 **用户协议 + 隐私政策** 页面（任务平台涉及报酬信息，属必配项）
- 提供 **用户注销入口**（强制要求，注销需删除或匿名化个人数据，含接取记录、凭证中的个人信息）
- **最小化收集**：MVP 不需要手机号就不要申请手机号授权；头像昵称用微信的「头像昵称填写能力」而非强制授权

### 2.3 内容安全（P0，强制）

微信要求 UGC 内容过内容安全检测，覆盖本平台所有用户输入：

| 内容 | 检测接口 |
|---|---|
| 昵称、任务标题/描述 | `security.msgSecCheck`（文本） |
| 任务、凭证图片 | `security.mediaCheckAsync`（异步，图片） |
| 提交凭证文字、互评内容 | `msgSecCheck` |

- 违规处理策略：发布时拦截（拒绝入库）+ 事后处置（下架/封禁）+ **用户申诉入口**
- 检测为异步接口，需配套"待检测 → 通过/不通过"的状态位与定时任务回查

### 2.4 域名与传输（P0）

- 全站 **HTTPS**；API 域名加入小程序后台「request 合法域名」
- 生产域名需 **ICP 备案**（国内服务器强制）
- MVP 不用 WebSocket（wss 需单独配置），如后续做消息实时推送再补

## 3. 安全审核

### 3.1 认证与授权

| # | 风险 | 等级 | 要求 |
|---|---|---|---|
| A1 | **越权（IDOR）**：按 id 操作的接口未校验资源归属，可审核他人任务、查看/修改他人凭证、取消他人接取 | **P0** | 所有 `GET/POST/DELETE /api/tasks/{id}...`、`/api/claims/{id}...` 接口强制校验：`task.publisher_id == 当前用户`、`claim.user_id == 当前用户`。校验逻辑抽成公共方法/注解，禁止在 controller 里散落判断 |
| A2 | JWT 密钥弱/硬编码，token 无法吊销 | P0 | HS256 + ≥32 字节随机密钥，存环境变量/配置中心，**禁止入 git**；token 7 天过期；JWT 载荷含 `jti`，预留黑名单实现踢人/封禁即时生效 |
| A3 | `session_key` 泄露 | P0 | `session_key` 只存服务端（用于 code2session、手机号解密），**严禁写入 JWT 或下发前端** |
| A4 | 管理端接口无独立鉴权 | P0 | 管理接口独立前缀 `/api/admin/*`，校验 `role == ADMIN`，与用户 token 分离 |
| A5 | 登录接口被刷（撞库/批量注册） | P1 | 登录、接取、提交、上传接口按 IP+用户维度限流 |
| A6 | 多端会话 | P2 | 预留 `jti` + 登录记录表，后续可按需实现单端登录 |

### 3.2 输入与注入

| # | 风险 | 等级 | 要求 |
|---|---|---|---|
| B1 | 参数未校验导致脏数据/异常 | P0 | `spring-boot-starter-validation` 全量 DTO 校验：非空、长度上限（标题 ≤50、描述 ≤2000、昵称 ≤30）、金额非负且 ≤2 位小数 |
| B2 | SQL 注入 | P0 | 全项目 **禁止 `${}` 拼接**，一律 `#{}` 参数化（MyBatis-Plus 天然参数化，主要防手写 XML 时踩坑） |
| B3 | XSS | P1 | 存储前过滤/转义；小程序端非 HTML 渲染天然防护，但若有富文本/WebView 场景需白名单过滤 |
| B4 | 接口数据量滥用（分页无上限） | P1 | 分页参数 `pageSize` 上限（如 20），服务端强制 |

### 3.3 文件上传（凭证/头像）

| # | 风险 | 等级 | 要求 |
|---|---|---|---|
| C1 | 上传可执行文件/伪装类型 | P0 | 扩展名白名单 + **校验文件 magic bytes**（不只信扩展名）；仅允许 jpg/png/webp |
| C2 | 超大文件拖垮存储/带宽 | P0 | 大小限制（如 ≤5MB），超限直接拒绝；上传接口限流 |
| C3 | 文件名不可控（路径穿越/重名） | P0 | 服务端生成随机文件名（UUID），**禁止使用用户原始文件名**；存储 key 按 `biz/{type}/{yyyyMM}/{uuid}.ext` 组织 |
| C4 | 恶意内容上架 | P0 | 直传后必须过 `mediaCheckAsync`，未通过前凭证不可见/不可结算（见 2.3） |
| C5 | 直传凭证泄露 | P1 | 客户端直传走 STS 临时凭证（短时效 + 最小权限目录），不用永久密钥 |

### 3.4 数据与密钥安全

| # | 风险 | 等级 | 要求 |
|---|---|---|---|
| D1 | 数据库暴露公网/弱口令 | P0 | 生产 DB 仅内网可达；独立最小权限账号（应用账号只授权业务库 DML，不做 DDL）；强口令 |
| D2 | 敏感信息明文存储 | P1 | 手机号（若收集）加密存储或脱敏展示；`openid` 打日志脱敏（`o****123`） |
| D3 | 密钥散落 | P0 | JWT secret、微信 appsecret、云存储密钥全部环境变量/KMS，配置文件只留占位符 |
| D4 | 日志含敏感信息 | P1 | 禁止打印完整 openid/手机号/token；统一日志框架控制 |

### 3.5 传输安全

- 全站 HTTPS（小程序强制），服务端可加 HSTS 头；内网调用走内网地址。

## 4. 可靠性审核

### 4.1 数据一致性（超卖与并发）

| # | 场景 | 要求 |
|---|---|---|
| E1 | 名额 N 并发接取 | 原子 SQL：`UPDATE task SET claimed_count = claimed_count + 1 WHERE id = ? AND claimed_count < quota AND status = 'OPEN'`；受影响行数 = 0 即满员。**事务边界 = 扣减 + 插入 claim** |
| E2 | 重复接取 | `task_claim` 唯一索引 `(task_id, user_id)` 兜底 + 状态校验（已有有效 claim 则拒绝） |
| E3 | 接口重复调用（客户端重试/连点） | 接取：唯一索引天然幂等；提交/审核：**状态迁移校验**（仅合法状态可流转，重复提交返回当前状态而非报错）；前端按钮防重 |
| E4 | 任务改价影响已接取者 | `claim.reward` 结算快照，审核结算以快照为准 |
| E5 | 定时任务与用户操作竞态 | 状态机迁移全部走"**CAS 式更新**"：`UPDATE ... SET status = ? WHERE id = ? AND status = 旧状态`，失败即说明已被并发修改，重新读取处理 |
| E6 | 对账 | 定时任务扫描不一致（如 claimed_count 与 claim 实际行数不符、SUBMITTED 超时未审核），记录并告警 |

### 4.2 状态机与审计

- 状态迁移合法性：枚举 + 迁移 map 校验，非法迁移直接拒绝（见评审建议第 6 条）
- **所有状态变更写 `task_status_log` / `claim_status_log`**：谁、何时、从哪到哪、原因。这是排查线上问题（尤其并发竞态）的唯一依据，必须做
- 关键操作（登录、接取、提交、审核、结算、封禁）写审计日志

### 4.3 定时任务可靠性

- **幂等 + 防重入**：单实例用 `@Scheduled`；多实例部署时必须加分布式锁（Redisson），防止同一任务被两个实例重复执行
- 失败重试：扫描任务记录失败批次，支持重跑；连续失败告警
- 时间字段用数据库时间（`NOW()`）而非应用服务器时间，防多实例时钟偏差

### 4.4 性能与容量

- 索引清单（建表时一次到位）：

| 表 | 索引 |
|---|---|
| task | `(status, claim_deadline)`、`(status, create_time)`、`(publisher_id)` |
| task_claim | 唯一 `(task_id, user_id)`、`(user_id, create_time)`、`(status, review_deadline)` |
| notification | `(user_id, is_read, create_time)` |
| task_status_log | `(task_id)` |

- 分页：MyBatis-Plus 分页插件，全表扫描禁止
- 缓存：任务列表/详情缓存 Redis，更新时**先删缓存再写库**（配合延迟双删或版本号），避免缓存与库不一致
- 限流：Redis 令牌桶/滑动窗口，登录、接取、提交、上传、通知读取分级限流（阈值做成配置项）

### 4.5 高可用与降级

- 应用无状态化（JWT 无 session 依赖）→ 支持 2+ 实例 + Nginx 负载均衡
- MySQL：MVP 单库 + **每日全量备份 + binlog**（恢复演练至少做一次）；预留主从
- Redis：开 AOF 持久化；**Redis 不可用必须优雅降级**（限流器降级为放行/本地计数，缓存降级直查库，设置短超时防止雪崩）
- 存储：上传失败返回明确错误码，前端可重试；凭证上传与业务提交解耦（先传文件拿 file_id，再提交业务）

### 4.6 可观测性

- 日志：logback + JSON 结构化 + `traceId`（MDC 贯穿一次请求），请求日志含耗时/状态码
- 健康检查：`/actuator/health` 接入负载均衡探活
- 指标/告警：MVP 至少接错误率、超卖失败数、定时任务失败数告警（邮件/企业微信机器人）；有条件上 Prometheus + Grafana
- 上线前确定日志采集与保留策略（防止日志把磁盘打满）

### 4.7 部署与发布

- 环境隔离：dev / test / prod 配置分离，prod 密钥绝不进仓库
- CI/CD：构建 + 单测 + 镜像（GitHub Actions / Jenkins）
- 发布：镜像 tag 版本化，支持回滚；小程序端后端接口变更注意**灰度兼容**（旧版本小程序还在线上）
- 资源配额：单文件大小、上传速率、单页数据量、图片尺寸均设上限

## 5. 对现有方案的增量修改建议

### 5.1 表结构新增

| 表 | 用途 | 说明 |
|---|---|---|
| `report` | 举报表 | 用户举报任务/凭证/互评，含处理状态；上架后平台审核用，且是内容安全闭环的一部分 |
| `audit_log`（或复用 status_log） | 关键操作审计 | 登录/接取/审核/结算/封禁记录 |
| `app_config` | 配置表 | 限流阈值、审核窗口、文件大小上限等可运行期调整，不重启发版 |
| `login_log` | 登录记录 | 安全审计 + 后续风控基础 |

`user` 表补充：`status`（正常/封禁）、`register_time`；封禁需支持踢人下线（配合 A2 的 jti）。

### 5.2 接口新增

- `POST /api/reports` — 举报（含被举报对象类型+id+原因）
- `POST /api/auth/logout` — 登出（作废 token）
- `DELETE /api/users/me` — 注销账号（隐私合规强制项）
- `/api/admin/*` — 管理端接口前缀（内容审核、封禁、统计），独立鉴权
- 上传：`POST /api/files/policy`（STS 临时凭证）或 MVP 直接 `POST /api/files`

### 5.3 配置项清单（进 app_config 或 application.yml）

限流阈值、审核超时窗口、自动通过开关、文件大小上限、内容安全检测开关、缓存 TTL、分页上限。
